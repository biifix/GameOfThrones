Design highlights:
- The pile is evaluated as a sequence, which makes the result depend on card order rather than just suit totals.
- Diamond resolution uses the last affected attribute, which avoids recomputing the whole pile from scratch for each effect decision.
- The design separates move legality from score resolution, which makes future bot strategies easier to extend.
- Bot decision logic is driven by external property configuration, so legal-bot behavior can change without rewriting core game flow.
- Smart-bot fallback to minimal play prevents repeated dead turns while still preserving rule-based decision priorities.

GoF design pattern used:
- Strategy Pattern.
- The bot decision logic is naturally suited to Strategy because legal-bot and smart-bot behavior are different move-selection strategies operating over the same game state.
- A legal bot can use a rule-based strategy, while a smart bot can use an optimisation-based strategy without changing the rest of the turn-processing code.

GRASP justification:
- Information Expert: `GameOfThrones` currently holds the hand, piles, and score state, so it is the natural place for pile evaluation and turn resolution.
- Low Coupling: separating move-choice behavior into bot strategies reduces direct dependence between turn execution and bot rules.
- High Cohesion: pile scoring, move legality, and bot decision logic are distinct responsibilities and should remain in focused methods or classes.
- Polymorphism: different bot types should vary by behavior through different strategy implementations instead of large conditional blocks.

Alternative GoF pattern considered:
- State Pattern.
- State is plausible because the smart bot changes between character-selection, attacking, defending, pass, and minimal-play modes.
- Strategy is the better final choice because the main variation here is how a move is selected, not how a long-lived object changes its entire behavior across many unrelated operations.
- State would be heavier for the current codebase and would introduce more mode-transition machinery than needed for the present feature scope.

Conclusion:
